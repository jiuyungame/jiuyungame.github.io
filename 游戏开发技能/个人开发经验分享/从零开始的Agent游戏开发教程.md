使用Agent进行游戏开发工作

**DeepSeek Harness 配置教程**

## 1 关于Agent工具使用的一些问题

**Q ：什么是Agent？**

A ：Agent 就是能自己拆解目标、调用工具并执行任务的 AI，区别于我们日常使用的问答对话大模型，Agent是可以真正应用于项目工程去进行实操的强大工具，在日常应付作业也有奇效（好好学习！！！）

**Q ：作为一名程序同学，Agent这么强大，我们是否还需要学习代码语言等基础知识？**

A ：这个答案是肯定的，常说命运需要掌握在自己手里，AI可以代替我们手写代码进行提效，但如果我们连AI写了什么都不明白的话，这种黑箱操作对大型项目是非常致命的。我认为AI的正确用法就是我们去提供脚本编写思路、进行边界限制，让AI去自动写来提效，这需要我们有代码的功底。

**Q ：这篇教程我们能学到什么？**

A ：先把初学者比较好接触的Agent工具配置起来，例如DeepSeek Harness ,WorkBuddy。本篇使用DeepSeek Harness，也就是后面提到的dsh，从申请API一直讲到能够在自己的项目文件夹里正常使用。后续再通过一个小项目去感受Agent在实际开发中的功效。

本篇以Windows电脑为例。Work Buddy这次先不展开，我们先把dsh这一条流程跑通，不然工具装了一堆，真正要用的时候还是不知道从哪里开始。

整个流程：申请API Key → 安装Node.js → 启动dsh → 配置模型和工作区 → 发一条任务检查效果。

## 2 准备工作

### （1）申请DeepSeek的模型API

Agent类似于人体的四肢，大模型类似于人体的大脑，而模型API类似于连接这两者的通道。我们这次就是通过DeepSeek API，把dsh和大模型连接起来。

首先进入DeepSeek的官网 https://www.deepseek.com/，点击下面的“使用API开放平台”，然后按页面提示注册或登录自己的账号。

![]({{ '/assets/wiki/agent-tutorial-01.png' | relative_url }})

图1 点击使用API开放平台

进入之后会看到用量信息，点击左侧的“API keys”。也可以直接打开 https://platform.deepseek.com/api_keys。

![]({{ '/assets/wiki/agent-tutorial-02.png' | relative_url }})

图2 左侧的API keys就是管理密钥的地方

### （2）创建密钥并检查余额

点击右侧的“创建API key”，名字起一个自己能认出来的就行，比如dsh学习。创建完成后，把完整的Key复制保存好，等会儿需要填到dsh里面。

![]({{ '/assets/wiki/agent-tutorial-03.png' | relative_url }})

图3 点击创建API key，已有的密钥不用照着截图填写

这里要注意，完整Key只在创建时显示，列表里带星号的那一串不能拿来用。如果忘记保存了，重新创建一个就好。Key相当于调用额度的钥匙，不要发到群里，也不要写进游戏代码或者上传到GitHub。

再看一下“用量信息”里的余额。网页聊天和API调用是两回事，网页能聊天不代表API就有余额。没有可用余额的话，先到“充值”页面按自己的预算处理，入门没必要一次充很多。截图里目前甚至是负数qaq。

想了解接口怎么用、怎么计费，可以从左下角的“接口文档”和“产品定价”进去看。我们这次使用dsh内置的DeepSeek配置。

接口文档入口在左侧菜单靠下的位置。计费规则和可用模型以平台当时的信息为准。

### （3）安装Node.js

接下来安装Node.js。简单理解，它是运行这套工具需要的环境，安装好之后会一起带上npm和npx，后面我们就是用npx启动dsh。

打开 https://nodejs.org/zh-cn/download，选择Windows和LTS版本。普通的Intel、AMD电脑一般选x64，ARM电脑选ARM64，不确定的话可以在Windows“设置 → 系统 → 系统信息”里看系统类型。

![]({{ '/assets/wiki/agent-tutorial-04.png' | relative_url }})

图4 下载下方的Windows安装程序 .msi

这里直接点下方的“Windows安装程序(.msi)”就可以。上面那块Docker命令先不用管，我们按普通Windows安装方式来。截图里的版本号不用一模一样，选择官网当前提供的LTS版本即可。

下载好之后双击安装，大部分选项直接Next就行，接受许可协议，保留默认安装组件和添加到PATH的设置，最后点击Install和Finish。单纯为了启动dsh，额外的原生模块编译工具可以先不装，后面真的提示缺少再说。

安装好之后，关闭之前开着的终端。接下来我们重新打开PowerShell，检查一下环境有没有装好

## 3 启动DeepSeek Harness

### （1）打开PowerShell并检查环境

按键盘上的Win+R，会弹出下面这个“运行”窗口。输入powershell，然后点击“确定”或者直接按回车，就能打开PowerShell。

![]({{ '/assets/wiki/agent-tutorial-05.png' | relative_url }})

图5 按Win+R，输入powershell后点击确定

打开之后，分别输入下面两条命令，每条输完按一次回车：

node -v
npm.cmd -v

两条都能显示版本号，就说明环境已经装好了。如果提示“无法识别”，先重新打开终端；还不行就重新安装

### （2）准备练习文件夹

接下来在D盘新建一个dsh-Test文件夹，也就是D:\dsh-Test。后面的截图都用这个目录，大家可以跟着建；

从“运行”窗口打开的PowerShell不一定在项目目录里，所以我们再输入下面这条命令，切换到刚才的文件夹。路径改成你自己的，双引号保留：

cd "D:\dsh-Test"，意思是转到这个文件夹下，目录并不固定，项目在哪就转到哪个目录下面。

### （3）输入启动命令

在PowerShell中输入下面这条命令，注意空格和中间的横杠不要漏掉：

npx @deepseek-ai/dsh web

第一次运行时，会问你是否安装对应的软件包，看到“Ok to proceed? (y)”之后，输入y再回车，等待下载完成就行。第一次会慢一些，先耐心等它完成。

![]({{ '/assets/wiki/agent-tutorial-06.png' | relative_url }})

图6 首次运行输入y确认；截图中的策略修改命令不是必做步骤

如果出现“无法加载npx.ps1，因为在此系统上禁止运行脚本”，把启动命令换成下面这一条即可：

npx.cmd @deepseek-ai/dsh web

截图最上方的Set-ExecutionPolicy是另一种处理方式，会修改当前用户的脚本执行策略。我们这里用npx.cmd就行，不需要先去改策略。

### （4）确认服务启动

成功后会出现类似下面的地址，并自动打开浏览器。如果没有自动打开，就复制自己终端输出的完整地址，在浏览器里打开。

dsh web: http://127.0.0.1:3080/?token=<本次启动的令牌>

终端先不要关，关了网页就连不上了。网址里的token不是API Key，带token的完整地址不要分享给别人。浏览器打开后，地址栏可能只剩127.0.0.1:3080，下一页的截图就是这种情况。

## 4 配置模型和工作区

### （1）找到设置并填入API Key

浏览器打开之后，界面大概如下图。左边是工作区和会话列表，左下角的齿轮就是“设置”，中间的大框是后面输入任务的地方。

![]({{ '/assets/wiki/agent-tutorial-07.png' | relative_url }})

图7 dsh主界面，设置在左下角

初次使用会要求填写API key，如果当时没配置，点击左下角“设置”，进入“模型”（英文界面是Settings → Models）。找到DeepSeek这一项，把前面申请的完整API Key粘贴进去，

### （2）添加并选择工作区

工作区简单理解就是这次让Agent工作的项目目录。点击输入框上方、文件夹图标旁边的名称或下拉箭头，就是下图红色箭头指的位置。第一次还没选目录的话，这里可能显示“选择工作区”。

![]({{ '/assets/wiki/agent-tutorial-08.png' | relative_url }})

图8 点击输入框上方的工作区名称

已有目录可以直接切换；要添加新目录，就找到添加工作区入口。左侧“工作区”这一行最右边也有一个带加号的文件夹图标。打开文件夹选择窗口后，选中刚才建好的dsh-Test，再点击右下角“选择文件夹”。

![]({{ '/assets/wiki/agent-tutorial-09.png' | relative_url }})

图9 在D盘选中dsh-Test，然后点击选择文件夹

### （3）核对工作区和模型

选择完成之后，回到会话页面，看输入框左上方的名称是不是已经变成dsh-Test。下图就是选好之后的样子，这一步别漏掉，不然可能让Agent在另一个项目里干活。

![]({{ '/assets/wiki/agent-tutorial-10.png' | relative_url }})

图10 左上方是工作区，右下方是模型选择入口

接下来点击输入框右下角的模型名称或旁边的下拉箭头，选择已经配置好的DeepSeek模型。截图里显示的是DeepSeek-V41-Flash Max。

输入框上方的“标准模式”和下方的“工作区内修改”是另外两个选项，这边不会解释，大家可以去官方文档进行深度理解。

如果这里还提示“选择模型”，先把模型选好再发消息。切换后如果旧会话仍然使用原来的模型，可以点击左侧“新会话”再试，已经发过消息的会话可能保留原来的模型设置。

以后做Unity项目时，工作区要选包含Assets、Packages、ProjectSettings的项目根目录，不要只选其中一个脚本文件夹。现在先用空目录把流程跑通就行。

## 5 检查是否配置成功

### （1）先发一条读取任务

先别急着让它“帮我写个3A大作”，我们用一个很小的任务检查一下。确认当前工作区是dsh-Test，把下面这段话发给它：

**请只读取当前工作区，告诉我当前目录里有哪些文件。如果是空文件夹就直接说明，不要创建或修改文件，也不要安装依赖。**

![]({{ '/assets/wiki/agent-tutorial-11.png' | relative_url }})

图11 Agent识别出dsh-Test是空文件夹

截图里它返回的是“当前工作区目录D:\dsh-Test是一个空文件夹”，条目总数是0。我们刚建的就是空目录，所以这个结果是对的。大家如果用的是已有文件的目录，就核对它列出的内容是不是和实际一致。

回复上方能看到“3次工具调用”，表示这次过程中调用了工具。大家的次数、耗时和用量不一定和截图一样，不用追求这些数字一致。重点是它读到了正确的目录，而不是只说一句“我可以帮你”。

### （2）再试一次写入文件

接着就在这个会话里发一个写入任务，看看它能不能真正操作文件，而不只是嘴上说完成了：

**请在当前工作区新建dsh-test.txt，内容写“dsh配置成功”。如果文件已经存在，请先告诉我，不要覆盖。完成后告诉我文件保存在哪里，不要改动其他文件。**

如果弹出操作确认，先看清楚它要做什么，确认是在练习目录里创建这个文件，再允许操作。具体哪些操作会询问，取决于当前权限设置。

![]({{ '/assets/wiki/agent-tutorial-12.png' | relative_url }})

图12 打开实际生成的文件，核对内容是否为dsh配置成功

完成后，自己到D:\dsh-Test里看看，找到dsh-test.txt并双击打开。像图里这样，记事本标签是dsh-test.txt，正文是“dsh配置成功”，才算写入成功。

资源管理器里可能只显示dsh-test，没有后面的.txt，这是隐藏了文件扩展名，不是文件名写错了。想看完整名称，可以在资源管理器的“查看 → 显示”里勾选“文件扩展名”。

能正常回复、能读对目录、能按要求写出文件，到这里这套配置就真正跑通了。后续再让Agent帮我们写具体功能。

### （3）以后怎么重新打开

用完后，回到运行dsh的终端按Ctrl+C停止服务；如果继续询问是否终止，按提示确认。下次还是按Win+R，输入powershell打开终端，再依次输入：

cd "D:\dsh-Test"
npx.cmd @deepseek-ai/dsh web

如果你的项目不在D盘，把第一条里的目录换成实际路径。重新启动时，以终端新输出的地址为准。

使用同一个Windows账号和同一套dsh配置时，一般不需要每次重新填写Key。网页打开后，确认工作区是这次要做的项目、模型已经选好，再从左侧打开原来的会话，或者点击“新会话”开始新的任务。

这里有三个名字容易混在一起：dsh-Test是项目文件夹，也就是工作区；“读取当前工作区文件列表”是截图里的会话名称；dsh-test.txt是Agent在文件夹里创建的文件。它们各管各的，不需要都取成一个名字。

后续让Agent改游戏项目之前，建议先用Git提交一个能正常运行的版本。AI写完之后自己运行、自己检查，真的改出问题了也能退回来。

## 7 常见问题

### （1）浏览器没有自动打开或网页连不上

先看终端里有没有出现“dsh web:”的启动地址。有的话，复制本次输出的完整地址到浏览器；没有的话，先看终端最后的报错。确认运行dsh的窗口还开着，不要只反复刷新网页。

如果明确提示3080端口被占用，可以换一个端口启动，再打开新输出的地址：

npx.cmd @deepseek-ai/dsh web --port 3081

### （2）网页开了 但是模型一直报错

提示Key无效或认证失败，先检查有没有漏复制、带空格，或者误用了带星号的Key；提示余额不足，就回到开放平台检查余额。网页打开只说明dsh启动了，不说明API一定配置好了。

如果是网络错误、超时或请求过于频繁，先确认网络正常，稍后重试。不要一边报错一边反复开新会话，很容易把真正的错误信息刷过去。模型不存在的话，重新选择当前列表里的模型，再开新会话测试。

### （3）输入框不能用 或者找不到项目文件

先检查模型有没有选好、工作区有没有选中，再核对目录路径。有时候只是选择了隔壁文件夹，Agent当然就看不到我们想让它看的内容。

### （4）安装一直卡住

首次运行需要下载软件包，先等它完成。如果最后明确报了网络或下载错误，保留最后几行报错，检查网络后再试；不要直接照着网上的建议去关闭证书校验。遇到版本兼容问题，再去官方说明里核对Node.js要求。（这里有一个邪修方法，下载Work Buddy让它帮你解决配置问题）

到这里，dsh的基础配置就完成了。后续我们再把需求拆小，一步一步让Agent写功能、运行、修问题，不要把整个项目丢过去就等着验收（该自己检查的还是得自己检查！！！）
